# Дизайн-система: Core Components Альфа-Банка

Источник: https://core-ds.github.io/core-components/master/?path=/docs/intro--docs
Назначение: все экраны клиента и андеррайтера собираем на официальной
дизайн-системе Альфы, а не рисуем с нуля. Кастом — только там, где в
библиотеке нет нужного (компонент вилки).

## Подключение (для Ф)

```bash
yarn add @alfalab/core-components @alfalab/icons-glyph
```

- Компоненты импортируются по одному (tree-shaking):
  `import { Button } from '@alfalab/core-components/button';`
- Типографика и базовые CSS-переменные — через пакет темы
  (см. раздел Themes в доке: темы `default`/`click`/`site`/`corp`/`mobile`).
  Для кабинета МСБ логичнее `default` (десктоп) или `corp` — решить на созвоне.
- Сетка и отступы — на CSS-переменных библиотеки (`--gap-*`, `--color-*`),
  свои px-значения не вводить.

## Маппинг наших экранов на компоненты

| Наш экран (из screens.md Ф) | Компоненты Core |
|---|---|
| Новая заявка: продукт, сумма, срок, цель, ИНН | `Input`, `AmountInput`, `SliderInput` (сумма), `RadioGroup`/`Tabs` (продукт), `Checkbox` (согласия), `Button` |
| Статус заявки / шаги | `Steps` или `ProgressBar` |
| Список пятен под вилкой | `List` + `Typography` + `Badge` (цена в п.п.) + кнопка закрытия; стоп-фактор — `Alert`/`Plate` с красным view |
| Ответ на пятно + загрузка документа | `Textarea`, `Attach` |
| Решение / иные условия | `Plate` + таблица вариантов на `Table` (у андеррайтера) или `RadioGroup` (у клиента) |
| Очередь андеррайтера | `Table` + `Status`/`Badge` (статусы заявки) |
| Уведомления («пятно закрыто», «ответ отклонён») | `Notification` / `Toast` |
| Модалки (подтверждение отмены заявки) | `Modal` |

Статусы заявки маппим на цвета `Status`/`Badge` один раз — словарь в одном
файле фронта, коды из `day1_backend_application-states.md`.

## Чего в библиотеке нет — делаем сами

**Компонент вилки** (17% [■■■■■] 26% + подписи краёв) — наш главный
визуальный артефакт, в Core такого нет. Делаем кастомно, но:
- цвета зон (зелёная/серая/красная) брать из CSS-переменных темы
  (`--color-light-status-positive` и т.п.), не хардкодить hex;
- цифры и подписи — `Typography` из Core;
- компонент должен уметь два режима: клиентский (вилка + зоны) и
  андеррайтерский (те же зоны + отметки офферов).

## Договорённости

1. Никаких сторонних UI-китов (MUI/Ant) рядом с Core Components — только он.
2. Иконки — `@alfalab/icons-glyph`, эмодзи в интерфейсе не используем
   (🔴 из ```concept.md``` заменяем на `Alert`/красный `Badge`).
3. Сторибук-документация — source of truth по пропсам; если пропс не
   находится, смотреть конкретный компонент на сайте, не гадать.
4. Демо-данные для разработки — из моков Б2, формат ответов уже
   зафиксирован в `day1_backend_external-mocks.md`.

## Открытый вопрос

- Какая тема: `default` vs `corp` для кабинета бизнеса? Быстрое решение —
  сверстать один экран (вилка + пятна) в обеих и выбрать на созвоне.
