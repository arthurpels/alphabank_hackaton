## Что в docs лишнее для сдачи

Явно лишних (устаревших или дублирующих) документов нет, но часть файлов — внутренняя кухня команды,
жюри она не нужна.

### Внутренние — для сдачи не нужны

| Файл | Что это | На него ссылаются |
|---|---|---|
| `day0_plan.md` | план первого дня | никто |
| `day1_plan_analytics.md` | план аналитика на день 1 | никто |
| `kanban.md` | доска задач T01–T5x | `AGENTS.md`, `scripts/create_issues.py` (заводит задачи на GitHub) |
| `kanban2.md` | доска ML-трека M01–M34 | `AGENTS.md`, `ai-policy.md` (таблица «правило игры → задача») |
| `release-check.md` | план проверки для аналитика | никто |
| `submission-docs.md` | этот файл — список документов для сдачи | никто |

Удалять не советую — лучше перенести в `docs/internal/`:
- `day0_plan.md`, `day1_plan_analytics.md`, `release-check.md`, `submission-docs.md` никто не упоминает, их можно переносить свободно;
- после переноса `kanban.md` и `kanban2.md` поправить пути в трёх местах: `AGENTS.md`, `scripts/create_issues.py`, `ai-policy.md`.

Канбаны можно и оставить на виду: они показывают процесс работы команды. Тогда в карте документации README
пометить их как «процесс разработки».

### Пограничные — лучше оставить

- **`tz_credits.md`** — копия ТЗ. Жюри она не нужна, но на неё опирается `requirements-checklist.md`, а `AGENTS.md` и нейросети используют её как источник требований.
- **`day1_frontend_design-system.md`** — как фронт использует компоненты Альфа-Банка. На неё ссылается `screens.md`; для критерия «качество пользовательского опыта» полезна.
- **`calibration.md`, `synthetic-population.md`** — калибровка модели (M19, M20). Прямо не требование ТЗ, но хороший материал для «потенциала развития»; на них ссылается `ml-quality.md`.
- **`demo-ml.md`** — как запускать ML на демо. Нужен проверяющему: на него ссылаются тестовые сценарии.

### Остальные файлы — нужны для сдачи

Они закрывают обязательные или рекомендованные пункты ТЗ (списки выше).

Единственное, что мешает жюри, — префиксы `day1_backend_…` и `day1_frontend_…`: по ним непонятно, что это
основные документы, а не черновики дня 1. Переименовывать рискованно (на них около 40 ссылок) — проще дать
в README карту документации.
