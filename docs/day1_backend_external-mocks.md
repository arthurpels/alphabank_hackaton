# external-mocks.md — моки внешних источников

> Версия 3: сверено с кодом (T18 — моки, T30 — закрытие пятен).

6 моков: БКИ, ЕГРЮЛ/ЕГРИП, ФНС, ОФД, маркетплейс, эквайринг (обязательные по
ТЗ — первые три). Формат каждого: запрос → пример JSON-ответа → какие пятна
закрывает / создаёт.

**Общие договорённости**
- Идентификатор запроса — ИНН (10 цифр для ООО, 12 для ИП). Этого достаточно,
  ЕГРЮЛ по ИНН всё остальное отдаёт сам.
- Все моки детерминированные: один ИНН → один и тот же ответ (требование
  воспроизводимости из concept.md). Данные пяти основных компаний-персонажей
  и тестовой «Теплицы» для M15 зашиты по их ИНН (см. `synthetic-data.md`).
- В ответах поле `source` — для журнала и для пятен (`источник` из черновика).
- Ошибки: `404` — ИНН не найден, `422` — кривой ИНН. Отдельного пятна
  «источник недоступен» нет: 404 → сообщение клиенту, пятно остаётся
  открытым; таймауты/500 обрабатывает бэкенд (T23).

## 1. БКИ (бюро кредитных историй)

**Запрос**
```
GET /mock/bki/v1/report?inn={inn}
```

**Ответ (ООО «Кофейня»)**
```json
{
  "source": "BKI",
  "inn": "7701234560",
  "credit_score": 712,
  "open_credits": [
    { "type": "OVERDRAFT", "bank": "АО «Банк»", "limit": 300000,
      "debt": 0, "opened_at": "2024-03-11" }
  ],
  "closed_credits": 3,
  "delinquencies": { "current": 0, "max_days_ever": 5, "last_12m": 0 },
  "inquiries_6m": 1
}
```

**Пятна**
- закрывает: `NO_DATA` «кредитная история неизвестна» (первичный расчёт вилки);
- пятен не создаёт: кредитная история всегда известна из БКИ и учитывается
  фактором `credit_history` (`delinquencies.last_12m`); `inquiries_6m` —
  справочное поле ответа, в скоринге не участвует;
- стоп-фактор: `delinquencies.current > 0` → `STOP_FACTOR` 🔴 неустранимый:
  мок БКИ не умеет `pay`, погасить просрочку действием нельзя.

## 2. ЕГРЮЛ / ЕГРИП

**Запрос**
```
GET /mock/egrul/v1/company?inn={inn}
```

**Ответ (ООО «Однодневка» — персонаж автоотказа)**
```json
{
  "source": "EGRUL",
  "inn": "7719999994",
  "name": "ООО «Однодневка»",
  "legal_form": "OOO",
  "status": "ACTIVE",
  "registered_at": "2025-08-01",
  "director": { "fio": "Иванов И. И.", "appointed_at": "2026-09-15",
                "is_mass": false },
  "address": { "value": "г. Москва, ул. Примерная, 1", "is_mass": true },
  "okved_main": "46.90",
  "founders_count": 1
}
```

**Пятна**
- закрывает: `NO_DATA` «компания не найдена в реестре» (базовая проверка по ИНН);
- создаёт неустранимые стоп-факторы:
  - `NEW_DIRECTOR` — директор назначен < 3 мес. назад;
  - `MASS_ADDRESS` — массовый адрес;
  - `LIQUIDATION` — статус != ACTIVE;
  - `YOUNG_BUSINESS` — возраст компании < 6 мес.;
- любой из них → автоотказ в `AUTO_CHECK`; вилка считается, остальные пятна не создаются;
- аномалий ЕГРЮЛ не создаёт.

## 3. ФНС

**Запрос**
```
GET /mock/fns/v1/debts?inn={inn}
```

**Ответ (ООО с долгом в ФНС)**
```json
{
  "source": "FNS",
  "inn": "7725555556",
  "tax_debt": { "amount": 3412, "currency": "RUB", "as_of": "2026-10-15" },
  "unfiled_reports": 0,
  "tax_system": "USN"
}
```

**Пятна**
- закрывает: `NO_DATA` «нет данных о налоговой нагрузке»;
- создаёт: `STOP_FACTOR` 🔴 «долг в ФНС 3 412 ₽» — устранимый, способ закрытия `PAY`;
- после повторного запроса (`tax_debt.amount = 0`) пятно закрывается —
  мок должен уметь переключаться по тестовому сценарию
  (например, `POST /mock/fns/v1/debts/pay { "inn": "..." }` обнуляет долг).

## 4. ОФД (онлайн-касса)

**Запрос** (подключение по согласию клиента — способ `CONNECT_SOURCE`)
```
POST /mock/ofd/v1/connect { "inn": "7701234560", "consent": true }
GET  /mock/ofd/v1/revenue?inn={inn}&months=12
```

Для скоринга используются 12 месяцев. При `months=24` доступны октябрь 2024 –
сентябрь 2026: Кофейня — пример несезонного спада, ООО «Теплица» (ИНН
`7740000005`) — повторяющийся спад в марте 2025 и 2026 для проверки `SEASONAL` (M15).

**Ответ (ООО «Кофейня» — падение в марте)**
```json
{
  "source": "OFD",
  "inn": "7701234560",
  "months": [
    { "month": "2026-01", "revenue": 1450000 },
    { "month": "2026-02", "revenue": 1520000 },
    { "month": "2026-03", "revenue": 830000 },
    { "month": "2026-04", "revenue": 1490000 }
  ],
  "share_of_total_revenue": 0.7
}
```

**Пятна**
- закрывает: `NO_DATA` «продажи через кассу не видны (~70% выручки)» —
  самое дорогое пятно «Кофейни», до −3,5 п.п.;
- создаёт: `ANOMALY` «выручка упала на 45% в марте» (детектор аномалий ML
  считает по ряду `months`), способ закрытия `ANSWER`;
- ответ `RENOVATION` («был ремонт») принимает **система**, если падение
  разовое и в следующем месяце выручка восстановилась (не ниже 90 % от
  предыдущего месяца). Иначе ответ уходит андеррайтеру (`ON_REVIEW`);
- договор подряда клиент может приложить — он сохраняется в `DOCUMENT`,
  но авторешение от него не зависит.

## 5. Маркетплейс (Wildberries)

**Запрос**
```
POST /mock/marketplace/v1/connect { "inn": "...", "api_key": "demo" }
GET  /mock/marketplace/v1/sales?inn={inn}&months=6
```

**Ответ (ИП, продавец на WB — ветка «иные условия»)**
```json
{
  "source": "MARKETPLACE",
  "inn": "590987654351",
  "months": [
    { "month": "2026-05", "gmv": 620000, "payout": 465000, "returns_pct": 12 },
    { "month": "2026-06", "gmv": 580000, "payout": 430000, "returns_pct": 14 }
  ],
  "rating": 4.6,
  "store_age_months": 14
}
```

**Пятна**
- закрывает: `NO_DATA` «продажи на маркетплейсе не видны» (`CONNECT_SOURCE`);
- для скоринга берём `payout` (к выдаче), а не `gmv`; высокий `returns_pct`
  (> 20%) → `ANOMALY` «доля возвратов»;
- именно этот персонаж получает «иные условия» (1 млн вместо 1,5 или
  овердрафт) — офферы считаются движком сетки по этим данным.

## 6. Эквайринг

**Запрос**
```
POST /mock/acquiring/v1/connect { "inn": "...", "consent": true }
GET  /mock/acquiring/v1/turnover?inn={inn}&months=12
```

**Ответ**
```json
{
  "source": "ACQUIRING",
  "inn": "7701234560",
  "months": [
    { "month": "2026-01", "turnover": 980000, "tx_count": 4200 },
    { "month": "2026-02", "turnover": 1010000, "tx_count": 4350 }
  ],
  "avg_ticket": 233
}
```

**Пятна**
- закрывает: `NO_DATA` «обороты по эквайрингу не видны» (`CONNECT_SOURCE`);
- создаёт: `ANOMALY` «разовое крупное поступление» / «обороты ×5 за месяц»
  (персонаж «Однодневка»; отказ ей дают неустранимые стоп-факторы ЕГРЮЛ —
  новый директор и массовый адрес, эквайринг лишь добавляет аномалию);
- расхождение с ОФД (> 15%) → `ANOMALY` «обороты по кассе и эквайрингу
  не сходятся».

## Персонажи

Данные пяти персонажей и их ИНН — в `synthetic-data.md` (единственное место,
раздел 1). Здесь не дублируем.

## Принятые решения

1. Репутация — вне MVP, направление развития (`domain-research.md`, T04):
   эндпоинта нет, код `REPUTATION` в `DATA_SOURCE` оставлен зарезервированным.
2. Таблица ИНН — только в `synthetic-data.md` у А.
3. Согласие на источник храним в БД: таблица `APPLICATION_SOURCE`
   (application_id, source_code, consent_given, connected_at); моки stateless,
   `consent` в запросе — только флаг (см. `data-model.md`).
4. Недоступность источника: отдельного пятна/режима нет; 404 → сообщение
   клиенту, пятно остаётся открытым; таймауты/500 — обработка на бэкенде (T23).
5. ИП-строитель: источник выручки — только загруженный договор (`UPLOAD`,
   `DOCUMENT`), отдельного мока нет (согласовано с `synthetic-data.md`, T22).
