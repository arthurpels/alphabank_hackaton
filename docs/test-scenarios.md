# Тестовые сценарии

Сквозные сценарии для пяти демо-персонажей и негативные проверки. Каждый шаг
можно пройти в интерфейсе или запросом к API; у каждого шага — ожидаемый
результат. Данные персонажей — в `synthetic-data.md`, варианты использования —
в `use-cases.md`, номера переходов — в `day1_backend_application-states.md`.

---

## 1. Подготовка

1. Запустить проект: `cp .env.example .env`, затем `docker compose up --build`.
   Все сервисы должны быть в статусе `healthy` (`docker compose ps`).
2. Перед каждым сценарием вернуть демо-данные в исходное состояние:
   `scripts/reset-demo`.
3. Интерфейс: `http://localhost:5173`. API: `http://localhost:8080/api/v1`,
   Swagger UI — `http://localhost:8080/swagger-ui.html`.

**Как работать через API.** Пути в сценариях указаны относительно
`http://localhost:8080/api/v1`. Пользователь передаётся в заголовке
`X-Demo-User` — его id из `GET /demo/users` или из таблицы ниже. Суммы в API —
в копейках: 2 000 000 ₽ = `200000000`.

| Персонаж | `X-Demo-User` | ИНН компании |
|---|---|---|
| ООО «Кофейня» | `00000000-0000-0000-0000-000000000101` | 7701234560 |
| ИП Петров (строитель) | `00000000-0000-0000-0000-000000000102` | 590234567822 |
| ИП Кузнецова (продавец на WB) | `00000000-0000-0000-0000-000000000103` | 590987654351 |
| ООО «Техснаб» (долг в ФНС) | `00000000-0000-0000-0000-000000000104` | 7725555556 |
| ООО «Однодневка» | `00000000-0000-0000-0000-000000000105` | 7719999994 |
| Андеррайтер | `00000000-0000-0000-0000-000000000901` | — |

**Как читать сценарий.** Колонка «Действие» — что сделать в интерфейсе,
«Запрос» — то же через API, «Ожидаем» — что должно получиться. Вилка — ставка
«от–до» в % годовых. После каждого шага с пятнами вилку можно сверить в
`GET /applications/{id}/fork-history`.

## 5. ML-сценарии

Адрес ML-сервиса — `http://localhost:8001`, интерактивная документация — `http://localhost:8001/docs`.
Для сценариев с живой моделью выполните `scripts/demo-ml-prepare live` и дождитесь `ready` в
`GET /health/llm`. Для проверки без Ollama используйте `scripts/demo-ml-prepare replay` или `off`.
Подготовка и запасные варианты подробно описаны в `demo-ml.md`.

| # | Что проверяем | Действие / запрос | Ожидаем |
|---|---|---|---|
| ML-01 | Версии движка и модели | `GET /health`, `GET /health/llm` | `/health` отдаёт `rulesVersion` и `engineVersion`; `/health/llm` — один из статусов `disabled`, `warming`, `ready`, `unavailable`, а в live также модель и digest |
| ML-02 | Цель решается словарём | `POST /purpose` `{"productCode":"EQUIPMENT","goal":"2 кофемашины и витрина для второй точки"}` | `status=DECIDED`, `purpose=MATCH`, `generatedBy=KEYWORDS`, `llm=null`; Ollama не нужна |
| ML-03 | Смысловой разбор и кеш | В live дважды `POST /purpose` `{"productCode":"EQUIPMENT","goal":"Гриндер и блендеры в кофейню"}` | оба раза `DECIDED`, `MATCH`, `generatedBy=LLM`, одна и та же цитата и версия промпта; во втором ответе `llm.cached=true`, нового вызова Ollama в логах нет |

| ML-09 | Replay без Ollama | `scripts/demo-ml-prepare replay`, затем `python3 scripts/demo_ml_check.py` | витрина проходит **8 из 8** без живой модели; записанные ответы совпадают с live, неизвестный вход даёт `UNAVAILABLE` |
| ML-10 | Качество и детерминизм золотых наборов | Команда `eval/run.py --check --report ../docs/ml-quality.md` из раздела 2 `ml-quality.md` | таблица в отчёте пересоздаётся, ответы двух прогонов совпадают на 100 %; сейчас gate возвращает 1, потому что точность цели 87,2 % < 90 % |
| ML-11 | Цель сверяется с деятельностью | В live `POST /purpose` `{"productCode":"EQUIPMENT","goal":"Две кофемашины и витрина для второй точки","okved":"56.30"}`, затем `{"productCode":"EQUIPMENT","goal":"кофемашины для второй точки","okved":"26.20"}` | в обоих `purpose=MATCH`; для кофейни `profile.status=FITS`, для производителя компьютеров — `DOES_NOT_FIT`; второй ответ уходит специалисту с причиной, статус заявки не `REJECTED` |
| ML-12 | Без LLM сверка деятельности пропускается | `scripts/demo-ml-prepare off`, повторить второй запрос из ML-11 | `purpose=MATCH`, `profile.status=NOT_CHECKED`; цель принята как обычно, одна эта сверка не отправляет ответ специалисту и не меняет решение |

Сквозная проверка решения, а не только ML-эндпоинтов:

```bash
scripts/check-determinism
```

**Скрипт стирает демо-заявки.** Он дважды проходит сценарии пяти персонажей, перезапускает `ml`,
сравнивает снимки, решения, офферы и вызывает `POST /applications/{id}/fork/verify`. Код выхода 0
означает, что проверки коллекции прошли и расхождений нет. `scripts/check-determinism --llm`
сравнивает один и тот же путь с выключенной и включённой моделью.
