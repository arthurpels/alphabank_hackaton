# AGENTS.md

Правила работы в репозитории — для людей и для нейронок (Claude Code, Cursor,
Codex и др.). Прочитай целиком перед первой задачей.

## О проекте

Прототип цифрового кредитного конвейера для малого бизнеса (хакатон
Альфа-Банка). Концепция «Белые пятна»: банк показывает условия кредита вилкой,
а рядом — список того, что он о клиенте пока не знает; клиент закрывает пятна,
и вилка сужается.

- Концепция — `docs/concept.md`
- ТЗ — `docs/tz_credits.md`
- Задачи и кто что делает — `docs/kanban.md` и доска на GitHub; ML-трек всей
  командой и правила детерминизма — `docs/kanban2.md`
- Статусы заявки — `docs/day1_backend_application-states.md`
- Модель данных — `docs/day1_backend_data-model.md`
- Моки источников — `docs/day1_backend_external-mocks.md`

Внутри compose сервисы обращаются друг к другу по имени:
`postgres:5432`, `backend:8080`, `ml:8001`, `mocks:8002`.

**Чужой модуль трогаем только через задачу на доске** или после того, как
договорились с владельцем. Нужна правка у соседа — заведи задачу, назначь на
него, напиши в чат.

## Документация

- `docs/` — только то, что идёт на сдачу жюри. Пишем так, чтобы понял человек
  не из команды.
- `.docs/` — рабочие заметки, черновики, логи экспериментов. Нейронка пишет
  сюда, а не в `docs/`. В git не попадает.
- Поменял контракт (OpenAPI, схему БД, статусы, формат мока) — обнови
  документ в том же PR. Документ и код не должны расходиться.
- Диаграммы — Mermaid прямо в md, без внешних редакторов.

## Git

- Работаем каждый в своей ветке, backend в backend, frontend в frontend и тд, отдельные ветки под задачи не заводим.
- Перед push — `git pull --rebase`, чтобы не плодить merge-коммиты.
- Коммит начинается с номера задачи: `T28: переходы статусной машины`.
- Пушим только то, что поднимается через `docker compose up` и не ломает
  чужие сервисы.
- `main` не форсим (`push --force` запрещён). Конфликт решает тот, кто пушит.
- После релизного тега (T51) в `main` ничего не пушим — только отдельная ветка.

## Правила для нейронок

1. **Не коммить и не пушь сама.** Коммитит человек, после того как посмотрел
   diff.
2. **Не добавляй соавторство** в коммиты и PR: никаких `Co-Authored-By`,
   «Generated with…» и подобных строк.
3. Не пиши комментарии в коде
4. Работай только в модуле своей задачи. Нужно поменять чужой модуль —
   остановись и скажи человеку.
5. Новая зависимость — только с фиксированной версией в lock-файле
   (`pom.xml`, `package-lock.json`, `requirements.txt` с `==`) и с записью в
   `THIRD_PARTY_NOTICES`.
6. Никаких платных API, платных подписок и закрытых моделей. LLM — только с
   открытыми весами, локально (ограничения ТЗ 02 и 08).
7. Никаких реальных внешних интеграций — только наши моки из `mocks/`
   (ограничение ТЗ 04).
8. Секреты и пароли — только через `.env`. В код и в `docs/` не пишем.
   Новая переменная — сразу в `.env.example` с демо-значением.
9. Весь пользовательский путь — внутри продукта: никаких email, SMS и
   мессенджеров в сценарии (ограничение ТЗ 05).
10. Не выдумывай названия статусов, пятен, полей и эндпоинтов — бери из
   документов выше. Не нашёл — спроси.
11. Рабочие заметки и планы — в `.docs/`, не в `docs/` и не в корень.

## Стиль кода

- **Общее:** коды статусов, типов пятен и источников — строго как в доках
  (`COLLECTING`, `NO_DATA`, `OFD`…), на английском. Тексты для пользователя —
  на русском.
- **Java:** пакет `com.alphabank.backend.<модуль>`; слои controller → service →
  repository; DTO отдельно от сущностей; переходы статусов — только через
  статусную машину; деньги — `long` в копейках.
- **Frontend:** только компоненты Core Components, без MUI/Ant; цвета и отступы —
  из CSS-переменных темы; словарь «статус → подпись и цвет» в одном файле.
- **Python:** форматирование и линт — `ruff`; типы в сигнатурах; скоринг строго
  детерминированный — одинаковый вход даёт одинаковый выход.

## Definition of Done

Задача переезжает в Done, когда:

- [ ] поднимается через `docker compose up` с нуля;
- [ ] не ломает чужие сервисы и их healthcheck;
- [ ] документ или контракт обновлён, если поменялся;
- [ ] пункты чек-листа в задаче на доске отмечены.

## Как запустить

```bash
cp .env.example .env
docker compose up --build
docker compose ps
```

Все сервисы должны быть в статусе `healthy`.
